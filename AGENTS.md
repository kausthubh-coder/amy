# Amy, for agents

Android-first calorie tracker: Expo SDK 56, React Native 0.85, TypeScript, no backend. One multiline note per day is the whole UI. Each completed line becomes a food entry, matched to its line by normalized text (`src/domain/lines.ts`). Everything is local: `src/storage` keeps the diary in month-sharded AsyncStorage. PRODUCT.md sets the product boundaries. PRIVACY.md is a contract the code must keep.

## Before you change anything

1. In a new worktree, `.agents/skills/worktree-amy/SKILL.md` (`npm ci`, `npm test`, a port of its own). `npm test` must be green before and after your change.
2. Read `.agents/skills/verify-amy/SKILL.md`. The app runs here as Expo web on a free port. There is no Android device or emulator, so camera, dictation, widgets, the soft keyboard and the splash stay unverified, and your report must say so.

## Where things are

- `App.tsx`: root shell, `amy://` deep-link routing, which sheet is open.
- `src/screens/TodayScreen.tsx`: the note editor, the calorie rail beside it, the dock, and estimate orchestration. The hardest file. Read `src/domain/lines.ts` first.
- `src/store/AppDataContext.tsx`: every state mutation and every persistence call. Nothing else writes the diary.
- `src/storage/`: load, save, export, import, and validation of anything read from disk or pasted by a person.
- `src/agent/`: OpenRouter client, prompts, response parsing, local matching of remembered foods. Pure TypeScript; the tests fake `fetch`.
- `plugins/withAmyAndroidWidgets.js`: generates the Android widgets at prebuild. Native only, no web equivalent.

## Rules the code does not state

- The note text and the entries must never disagree. An entry with no visible line still counts in the totals. A change to line pairing, undo, dictation, day switching or import needs a test in `tests/lines.test.ts` or `tests/localDataStore.test.ts` that checks what the person sees.
- Loading never replaces unreadable data with a fresh diary. Storage problems raise `StorageLoadError` and the recovery screen handles them.
- Nothing leaves the device except what PRIVACY.md lists. A new network call, permission, or stored field goes into PRIVACY.md in the same change.
- Numbers people type go through `parseUserNumber` in `src/utils/number.ts`: "1,200" is twelve hundred.
- Colors come from `src/theme.ts`, chosen for WCAG contrast: `purpleButton` for filled buttons, `pinkText` for pink text, `dim` never on `panel2`.
- `android/` and `ios/` are generated by `npx expo prebuild --platform android --no-install` and ignored by git. Run prebuild to check a native config change (splash, permissions, widgets) and read the generated files; never commit them.

## Done means

`npm test` is green, the verify skill's journey for the feature you touched passes with evidence saved, and PRIVACY.md and this file are still true.

Ship only with `.agents/skills/ship-amy/SKILL.md`, and only when the maintainer says ship or release: it bumps the version, merges the PR, builds the signed APK on EAS and publishes the GitHub release.
